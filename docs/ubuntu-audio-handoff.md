## 背景和目标

- 用户提供的安装镜像为 `ubuntu-26.04.1-desktop-amd64.iso`，对应 Ubuntu 26.04.1 LTS、x86-64。尚未启动到已安装的 Linux，因此实际安装版本和更新状态未确认。
- 用户期望 Windows、Linux 双端可以通话并共享画面；共享窗口时只共享对应应用的声音，共享整个屏幕时共享其他应用的声音，不能把映伴通话的声音回传给对方。
- 任意一方说话时，视频或应用声音应降低，共享端和观看端都能听清人声；说话停止后恢复原音量。Linux 版界面应继续沿用映伴现有暖色界面。
- 保持现有 GitHub 仓库和署名；用户已删除 Gitee 仓库，不需要向 Gitee 推送。

## 继续工作

在 Ubuntu 26.04 环境中，先确认系统实际版本及音频服务，然后安装依赖并运行测试：

```bash
cat /etc/os-release
pactl info
sudo apt update
sudo apt install -y pulseaudio-utils pipewire pipewire-pulse wireplumber dbus-x11
npm ci
npm test
bash scripts/test-linux-audio.sh
npm run dist:linux
```

`scripts/test-linux-audio.sh` 会尝试在独立的临时 PipeWire 会话中使用虚拟声卡与合成音调验证采集、排除、降音和音量恢复，不应连接用户当前的音频服务。该脚本尚未实际运行，失败时需要先排查并修复，不能把它的存在当作测试通过。

接下来至少需要：

1. 在 Ubuntu 26.04 的真实 PipeWire 环境运行并修复上述集成测试，确认 `parec --monitor-stream`、进程元数据、混音时序以及监控流与音量的先后关系。
2. 在 Ubuntu Wayland 桌面确认系统选择器能正确选择屏幕和窗口，手动选中的声音应用与画面对应，应用退出或重新播放后行为正确。检查缺少工具或音频服务故障时的提示。
3. 使用 Windows 与 Ubuntu 两台设备、真实麦克风和耳机实测：单应用隔离、整屏多应用、观看端人声不会回传、双方说话时共享端与观看端都降音、停止后音量恢复，以及蓝牙设备和常用浏览器的表现。
4. 回归 Windows 功能及 Linux 安装包启动，验证 Windows 冒烟测试未完成的问题，并检查无界面干扰的测试是否能够稳定结束。
5. 完成代码审查及必要修复后，再决定合并、构建和发布；目前没有新安装包和新发布版本。

注意：Linux 应用音频依赖声音服务报告可识别的进程信息。部分沙盒应用、共用音频进程的浏览器、多声道或自定义 PipeWire 配置需要特别检查；尚不能保证与 Windows 的采集行为完全一致。
